# Research Next Steps

## 1. Purpose

This document records the remaining research and writing activities required to move the VREdu dissertation from draft form towards final submission.

## 2. Immediate Writing Tasks

The immediate priorities are:

1. Proofread the abstract.
2. Refine the research question and ensure that the conclusion answers it directly.
3. Check that the aims and objectives are measurable and linked to evidence.
4. Improve transitions between literature review sections.
5. Remove repeated explanations of the same subsystem.
6. Separate implementation description from evaluation interpretation.
7. Check that all claims about educational benefit are supported by evidence.
8. Standardise terminology such as rule-based, learner profile, LLM, virtual environment, and adaptive feedback.

## 3. Literature Tasks

The literature review should be checked for:

- accurate source details,
- consistent citation style,
- complete reference entries,
- correct author names,
- correct publication years,
- consistent use of italics,
- and alignment between in-text citations and the reference list.

Each source should be connected explicitly to a project decision. A literature paragraph should explain not only what another study found, but also how that finding influenced VREdu.

## 4. Evaluation Tasks

The evaluation chapter should be strengthened by:

- adding a clear table of test scenarios,
- recording expected and observed outcomes,
- identifying which tests were automated and which were manual,
- including screenshots where they provide evidence,
- distinguishing successful tests from unresolved issues,
- explaining limitations of the evaluation,
- and avoiding unsupported claims about learning gain.

## 5. Technical Verification Tasks

The final implementation should be checked against the dissertation in the following areas:

- scene names,
- algorithm count,
- keyboard shortcuts,
- level count,
- flashcard behaviour,
- session-summary behaviour,
- learner profile persistence,
- LLM service providers,
- API-key handling,
- and final controller/input behaviour.

Any mismatch should be corrected in either the code, the documentation, or the dissertation so that all three sources describe the same system.

## 6. Repository Tasks

The repository should contain:

- a concise root `README.md`,
- a clearly ordered `docs/` folder,
- a `research/` folder,
- relevant screenshots,
- setup instructions,
- issue logs,
- testing records,
- and a final issue-resolution document.

The research documents should not replace the implementation documents. They serve different purposes:

- `docs/` explains the software project.
- `research/` explains the preparation and evaluation of the dissertation.

## 7. Final Submission Checklist

Before submission, confirm:

- The final project opens using the documented Unity version.
- The final build can be produced or supplied.
- The repository contains the final documentation.
- The dissertation uses one consistent citation style.
- All figures and tables are numbered in order.
- All screenshots have captions.
- All screenshots are referenced correctly.
- All Markdown links work.
- No placeholder text remains.
- No draft comments or contradictory claims remain.
- Limitations are stated honestly.
- The conclusion answers the research question.
- Future work is clearly separated from completed functionality.

## 8. Final Research Position

The final dissertation should present VREdu as a technically structured and critically evaluated educational prototype. Its strongest evidence concerns the architecture, rule-based feedback design, station extensibility, session modelling, and documented engineering process.

Claims concerning improved learning outcomes, increased retention, or superiority over traditional teaching should be presented as future evaluation opportunities unless supported by a completed controlled study.

The research preparation process is complete when the dissertation, repository documentation, software implementation, and evaluation evidence are internally consistent.
